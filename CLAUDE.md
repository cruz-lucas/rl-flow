# CLAUDE.md

rl-flow is a JAX-based framework for composing reinforcement-learning experiments as node-graph
workflows, then validating, compiling, and running them into reproducible run directories. It is a
uv + pnpm monorepo. This file has two parts: behavioral guidelines, then project context.

---

## Behavioral guidelines

Bias toward caution over speed. For trivial tasks, use judgment.

### 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them — don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

### 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

### 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it — don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: every changed line should trace directly to the user's request.

### 4. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" → "Write tests for invalid inputs, then make them pass"
- "Fix the bug" → "Write a test that reproduces it, then make it pass"
- "Refactor X" → "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:

```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

In this repo, "verified" for training-code changes means numbers, not vibes — see
"Refactoring the training code" below.

## Layout

| Path | What it is |
|------|------------|
| `packages/core/rlflow/` | Core package `rlflow`: graph model, compiler, registry, schemas, execution, storage, tracking, analysis, CLI |
| `packages/builtin_components/rlflow_builtin/` | Built-in components: tabular agents (`tabular/`), DQN (`dqn/`), environments (gridworld/riverswim/sixarms/navix), runners |
| `packages/builtin_components/rlflow_builtin/dqn/` | DQN split into `config` / `state` / `networks` / `replay` / `intrinsic` / `policies` / `training`; `training.py` re-exports moved names for back-compat — preserve those re-exports (tests and `dataset_analysis` import through `dqn.training`) |
| `apps/api/rlflow_api/` | FastAPI backend (`create_app` in `main.py`); shared route helpers in `routes/_common.py`. Keep pandas OUT of the API import path (use `rlflow.analysis.parameters`, not `analysis.loading`) |
| `apps/web/` | React + Vite frontend (`@rl-flow/web`) |
| `configs/` | Workflow / sweep / cluster YAML configs — every path referenced in docs must exist (`tests/unit/test_docs_examples.py` enforces this) |
| `docs/` | MkDocs Material sources; `docs/reference/` is generated by `scripts/generate_docs_reference.py` |
| `tests/` | pytest suite (`unit/`, `integration/`, `analysis/`, `bench/`, `fixtures/`) |

## Commands

Everything is wrapped in the `Makefile` — run `make help`. The common ones:

```bash
make install        # uv sync (dev + analysis) and pnpm install
make test           # uv run pytest
make check          # lint + format-check + mypy(core) + tests — the pre-PR gate
make bench          # throughput guard (steps/sec) for the JAX hot loop
make docs           # generate reference pages + mkdocs build --strict
make web-lint       # eslint + prettier check for apps/web
```

Run an experiment end-to-end:

```bash
uv run rlflow workflow validate configs/workflows/tabular_q_learning_riverswim.yaml
uv run rlflow run configs/workflows/tabular_q_learning_riverswim.yaml --backend local
uv run rlflow report <run_dir>                  # single-run summary + learning curve
uv run rlflow components describe <id>          # config keys/defaults for YAML authoring
```

## Conventions & quality gates

- Invoke the CLI as `uv run rlflow ...`; keep `make check` green.
- CI (`.github/workflows/ci.yml`) runs ruff + mypy(core) + pytest and the web lint/build/tests on every PR.
- **Ratchets, don't floods** — several gates are intentionally lenient and meant to tighten over time.
  Don't add new violations; remove a ratchet only by making its scope clean first:
  - ruff: `E501`, `UP042` in the ignore list (`pyproject.toml`).
  - mypy: `rlflow_builtin.*` / `rlflow_api.*` have `ignore_errors` overrides; `packages/core` is enforced.
  - eslint: `react-hooks/set-state-in-effect` is warn-only (8 pre-existing sites).
- Reproducibility is a first-class feature: every run writes `manifest.json`
  (`rlflow/tracking/manifest.py`) capturing git SHA, seeds, dependency versions, and config hashes.
  Don't regress it.
- Third-party compute components execute via
  `compile_target={"runtime": {"entry_point": "pkg.module:run_training"}}` on their `ComponentSpec`;
  worked example in `tests/fixtures/external_agent/`, contract in `docs/concepts/components.md`.

## Refactoring the training code

The RL math in `rlflow_builtin` is only trustworthy under numeric proof. For any
behavior-preserving change to `tabular/training.py` or the `dqn/` package:

1. Capture a fixed-seed baseline BEFORE touching anything (run every affected code path; dump
   q-tables/returns/metrics to a scratch `.npz`/JSON).
2. Refactor.
3. Re-run and assert `allclose` against the baseline, run `make bench` (throughput must hold),
   and run the full suite.

Never claim a training-code refactor is safe from green tests alone — the suite is coarse.
For large code moves, compute function spans with `ast` and check that no moved function
references a staying definition (prevents circular imports) before cutting.

## Gotchas

- The pinned JAX is newer than any stable `tensorflow-probability` release, so navix (via rlax/distrax)
  requires a **tfp nightly** — pinned as `tfp-nightly` in `pyproject.toml`. If `uv sync` can't find that
  nightly (nightlies are eventually purged from PyPI), bump it to a newer nightly compatible with the
  pinned JAX rather than removing it.
- `uv sync` prunes extras you omit: syncing `--extra dev` alone removes mkdocs (docs extra) and can
  leave the env inconsistent. Sync all needed extras together:
  `uv sync --extra dev --extra analysis --extra docs`.
- Run heavy JAX tests on CPU with `JAX_PLATFORMS=cpu` for determinism/speed.
- `rlflow run --backend local` is asynchronous (the LocalExecutor returns while training continues);
  to run synchronously, compile then `bash <run_dir>/command.sh`.
- The runner's registry does entry-point discovery at runtime — external component packages must be
  installed in the same environment the compiled `command.sh` executes in.
